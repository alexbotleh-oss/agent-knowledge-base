# agent-knowledge-base

Общая база опыта и автономный протокол для нескольких проектов и стеков.

## Цели
- Агрегировать опыт разных проектов с сохранением происхождения.
- Исключить циклы «правка ИИ → проверка пользователя».
- Требовать самостоятельной диагностики, тестирования и отчётности.
- Поддерживать Flutter, Flet, Python, Java, HTML/PWA, C++, C#, Rust, JavaScript и Go.
- Добавлять стеки через реестр и адаптеры без изменения маршрутизатора.

## Структура
- `core/guardrails.md` — ограничения автономного агента.
- `core/universal_instructions.md` — протокол выполнения задач.
- `core/stack_registry.json` — детекторы стеков.
- `core/validation_router.sh` — маршрутизация проверок.
- `core/validation_rules.sh` — общие функции проверок.
- `projects/CARD/` — контекст, решения и уроки CARD.
- `stacks/<stack>/{lint,test,build}.sh` — адаптеры.
- `tools/validate_project.sh` — единая точка входа.
- `tools/generate_report.sh` — генерация отчёта.
- `tools/install_into_repo.sh` — безопасное копирование недостающих файлов.
- `templates/patch_plan.md` — шаблон плана патча.
- `.github/workflows/validate.yml` — CI.

## Запуск
```bash
chmod +x core/*.sh tools/*.sh stacks/*/*.sh
tools/validate_project.sh /path/to/project
tools/generate_report.sh /path/to/project
```

Адаптеры не устанавливают зависимости автоматически. Отсутствующий инструмент отмечается как `SKIP`; `STRICT_VALIDATION=1` превращает пропуск обязательной проверки в ошибку. Наличие адаптера не доказывает, что тесты существуют или визуальная проверка выполнена.

Для UI/PWA агент должен по возможности запустить приложение, получить скриншот, проверить адаптивность, переполнение, ключевые состояния и действия, затем сохранить доказательства. Если браузер/рендерер недоступен, указать `VISUAL=SKIP` и причину.

Обычные обратимые инженерные шаги выполняются без лишних подтверждений. Перед рискованными действиями проверяются состояние репозитория и откат. Необратимые операции и удаление данных требуют соответствующих полномочий.
