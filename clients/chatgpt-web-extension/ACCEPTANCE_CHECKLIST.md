# Ручная приёмка краткосрочной памяти Римы и библиотеки вложений

**Статус:** чек-лист для будущей проверки на реальном устройстве. Ни один пункт не считается пройденным до наблюдаемого результата.

## A. Установка и безопасность

- [ ] Установить распакованное расширение из проверенной ревизии ветки `feature/dialogue-stm-source-references-20261017`.
- [ ] Убедиться, что расширение загружается без ошибок и popup открывается.
- [ ] На том же устройстве запустить Python bridge с loopback bind, случайным bearer token длиной не менее 32 символов и точным `chrome-extension://<ID>` в allowlist.
- [ ] В popup скопировать показанный extension origin и сравнить его с allowlist сервера посимвольно.
- [ ] Ввести явный project ID и тот же bearer token; сохранить настройки.
- [ ] Подтвердить, что токен хранится только в профиле браузера и не считается зашифрованным секретом.

## B. Сбор и восстановление окон

- [ ] Отправить короткое безвредное текстовое сообщение в ChatGPT через расширение.
- [ ] Убедиться, что отправка не происходит до локальной регистрации хода.
- [ ] Дождаться ответа; открыть popup и убедиться, что ход отмечен как завершённый.
- [ ] Отправить ещё сообщения в текущем чате и в другом чате; убедиться, что глобальное окно охватывает последние пять завершённых пар по времени получения, а окно текущего чата содержит последние пять пар именно этого чата.
- [ ] Проверить, что одна пара, входящая в оба окна, копируется в контекст один раз и помечается обоими scope.
- [ ] Проверить незавершённый ход: он должен остаться видимым отдельно от пяти завершённых пар.
- [ ] Перезагрузить вкладку/браузер и проверить сохранность локального журнала.
- [ ] Проверить оба явных действия popup: скопировать контекст и вставить его в пустой composer. Вставка не должна перезаписывать существующий черновик и не должна отправлять сообщение автоматически. Вручную отправить вставленный контекст и проверить, что он содержит статус покрытия, обе истории и ограничения.

## C. Вложения и проектные границы

- [ ] После того как сообщение с файлом уже отправлено в ChatGPT, открыть popup и выбрать точный ход-источник в этом же чате.
- [ ] Повторно выбрать тот же файл с устройства и выполнить ручной импорт.
- [ ] Убедиться, что popup показывает `LINKED`/ `ALREADY_LINKED`, а выбранный ход содержит только attachment ID, project-library reference, SHA-256, размер и безопасные метаданные — без байтов файла и абсолютного пути.
- [ ] Убедиться, что файл находится в приватной локальной библиотеке проекта, а не в Git-репозитории.
- [ ] Повторить импорт того же файла для того же хода: библиотека не должна создавать вторую копию объекта.
- [ ] Импортировать тот же файл в другой проект: ссылка и объект должны быть изолированы по project ID.
- [ ] Проверить разрешение ссылки через `resolve_attachment()`; повреждённый или отсутствующий объект не должен сообщаться как AVAILABLE.

## D. Негативные проверки

- [ ] Неверный/отсутствующий токен → отказ 401, файл не регистрируется.
- [ ] Origin вне allowlist → отказ 403.
- [ ] Пустой или невалидный project ID / source turn → отказ без ложной ссылки.
- [ ] Файл больше 25 MiB → отказ 413.
- [ ] Остановленный bridge → popup сообщает об ошибке; сообщение ChatGPT не изменяется.
- [ ] Повреждённый JSONL-реестр → импорт блокируется до создания нового объекта.
- [ ] Попробовать передать лишнее поле/payload вместо ссылки в `LINK_ATTACHMENT` → отказ валидации.
- [ ] Проверить, что bridge не пишет байты файла или bearer token в логи.

## E. Критерий приёмки

Пункт принимается только при наблюдаемом результате на целевом устройстве. CI и синтетические тесты проверяют кодовые контракты, но не доказывают, что расширение работает в установленной версии Yandex Browser Android, что localhost доступен из popup или что CORS/permissions ведут себя ожидаемо.

Отдельно фиксировать:
- модель устройства и версию Android;
- версию браузера;
- commit SHA расширения;
- результат каждого пункта: PASS / FAIL / BLOCKED / SKIP;
- скриншот или обезличенное доказательство, не включающее текст личных сообщений, токены и содержимое файлов;
- точный блокер и следующий шаг для каждого FAIL/BLOCKED.

**Не считать полную систему памяти готовой**, пока не пройдены реальные проверки захвата сообщений, окон, ручного импорта/разрешения вложений и передачи контекста в новый чат. Автоматический захват файла из ChatGPT и автоматическое внедрение окон в запрос модели остаются отдельными незавершёнными задачами.
