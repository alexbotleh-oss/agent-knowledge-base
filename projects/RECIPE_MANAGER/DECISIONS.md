# RECIPE_MANAGER — решения и требования пользователя

> Этот файл фиксирует принятые пользователем требования и решения, а не утверждает, что они все уже реализованы.

## DI-001 — Сопоставление ингредиентов через нормализацию
- **Статус:** принятое требование; реализация и регрессия в текущем состоянии не подтверждены.
- **Источник:** история чата «Что приготовить»; обсуждение импорта рецептов и нормализации ингредиентов (доступная история включает сообщения за сентябрь 2026).
- **Решение:** перед поиском запасов нормализовать название: регистр, грамматические формы, окончание/падеж, порядок слов и ограниченный словарь синонимов.
- **Ограничение:** нормализованная строка — поисковый ключ; исходный текст ингредиента в рецепте сохраняется.
- **Примеры:** «масло оливковое» ≈ «оливковое масло»; «яйца/яйцо/куриное яйцо»; «лук/репчатый лук»; «говядина/мясо говяжье»; «свинина/мясо свиное»; «мука/мука пшеничная».

## DI-002 — Явные семейства лука
- **Статус:** принятое пользователем правило.
- **Решение:** «лук», «белый лук», «жёлтый лук», «репчатый лук» сопоставлять с продуктом «Репчатый лук». «Красный лук» и «Зелёный лук» — отдельные варианты и не должны нормализоваться к репчатому.
- **Источник:** доступная история чата; пользовательские примеры.

## DI-003 — Явные семейства риса
- **Статус:** принятое пользователем правило.
- **Решение:** просто «рис» в рецепте по умолчанию искать как «Длиннозерный рис»; «рис для плова» и «пропаренный рис» искать как «Пропаренный рис»; круглозерный рис остаётся самостоятельным.
- **Ограничение:** не сопоставлять по подстроке с рисовой мукой/рисовым маслом.

## DI-004 — Количество и единицы
- **Статус:** принятое требование; код в текущей версии не подтверждён.
- **Решение:** строка «Яйца 1 шт. = 60 г» означает 1 шт.; 60 г — эквивалент/справочная масса. Нельзя ошибочно интерпретировать 60 как основное количество.
- **Источник:** история чата, обсуждение дефекта разбора импорта.

## DI-005 — Доступ к базе данных в HTML
- **Статус:** требование; последнее состояние требует функциональной проверки.
- **Решение:** доступ к SQLite recipes.db в HTML должен быть сделан по аналогии с index_db_path.html. Обсуждался выбор файла базы и подключение через API.
- **Ограничение:** прямое чтение выбранного .db из браузера — read-only режим в описанном решении; запись/удаление в БД требует API. Это было изложено в сообщении ассистента, но не подтверждено отдельным функциональным тестом.

## DI-006 — Управление рецептами и нутриентами
- **Статус:** требования пользователя.
- **Решение:** сохранить одиночное и массовое удаление рецептов, добавление из базы, показывать ккал/100 г и белки/жиры/углеводы; не допускать регрессии этих функций при изменениях HTML.
- **Решение по импорту:** импортировать с food.ru и 1000.menu, разбирать ингредиенты/категории/БЖУ, иметь возможность выбирать несколько рецептов.
