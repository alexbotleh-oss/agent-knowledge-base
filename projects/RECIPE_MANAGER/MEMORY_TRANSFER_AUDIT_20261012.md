# Отчёт проверки переноса — RECIPE_MANAGER HTML category regression

- **Дата:** 2026-10-12
- **Источник:** текущий чат проекта «Что приготовить», доступные сообщения и два пользовательских скриншота.
- **Ветка изменения памяти:** `learn/recipe-manager-html-category-regressions-20261012`
- **Базовая ветка:** `handoff/recipe-manager-chat-continuation-20261012`
- **Базовый коммит:** `8abf56a281fd55d94adf6444e65b58fefb500b01`
- **Область:** перенос опыта в `agent-knowledge-base`; приложение не редактировалось и APK не собирался.

## Что проверено перед изменениями
- Прочитан `README.md` репозитория и его правила памяти: проектная история разделяется на актуальное состояние, состояние задачи, журнал событий, решения, уроки и handoff; журналы преимущественно append-only.
- Просмотрена текущая структура `main` через GitHub tree. До предыдущего handoff в `main` каталог `projects/RECIPE_MANAGER` отсутствовал.
- Сравнены `main`, `handoff/recipe-manager-20261012`, `handoff/recipe-manager-chat-continuation-20261012` и `learn/B77-html-pwa-experience-20261012`. Выбранная базовая handoff-ветка уже содержала предшествующий контекст RECIPE_MANAGER; не стали повторно переписывать ранние события о SQLite, КБЖУ, Food.ru/1000.menu и Flet.
- Проверены текущие ID событий/уроков: последнее событие было `EVT-20261012-006`, последний урок — `LESSON-RM-009`. Новые ID назначены последовательно: `EVT-20261012-007`, `LESSON-RM-010`.

## Добавленные факты
- `EVENT_LOG.md`: хронология HTML-макета v16–v19, что пользователь подтвердил, что осталось сломанным, и какие проверки не проводились.
- `DECISIONS.md`: явное требование пользователя к работающему выбору food/non-food при ручном добавлении или к работающему переключателю/галочке существующего продукта.
- `LESSONS.md`: правило считать UX-контрол неработающим (FAIL), когда это сообщает пользователь, и проверять реальный путь создания/сохранения/перезагрузки/фильтрации/редактирования.
- `PROJECT_STATE.md`, `TASK_STATE.md`, `HANDOFF.md`: статус этой HTML-подзадачи отдельно от актуального Android/Flet трека.
- `events.jsonl`: структурированное событие `EVT-20261012-007` со статусами фактов/гипотез, источниками и следующим безопасным шагом.
- `lessons.jsonl`: структурированный урок `LESSON-RM-010`.

## Проверки
- Изменения всех 8 затронутых файлов перечитаны после записи через GitHub Contents API.
- Проверены наличие новых разделов, имена файлов v16–v19, ссылки между Markdown и JSONL, упорядоченность ID.
- Структурный локальный прогон JSON/JSONL валидатора **ещё не выполнялся в этой среде**; его должен подтвердить CI после открытия PR. Не выдавать локальный validator PASS за факт.
- Предыдущая запись в handoff упоминает успешный CI для более раннего commit/PR #6; это **не является** результатом проверки текущих изменений.
- Функциональная проверка макета не выполнялась в рамках memory-only работы. По последнему прямому пользовательскому сообщению классификация остаётся FAIL; причина не установлена.

## Полнота и пробелы
- Перенесена вся доступная в текущем контексте история про v16–v19 и категорию продуктов, включая неудачную попытку объяснить v19 как исправленную.
- Полный экспорт всех сообщений всех связанных чатов и всех вложений не предоставлен в этой сессии; перенос честно помечен `PARTIAL`, не `COMPLETE`.
- Исходники v16–v19 не были повторно материализованы и запущены в этой задаче; вывод о корне ошибки не делался.
- PR не следует сливать в `main` без явного разрешения пользователя.
