# RECIPE_MANAGER — уроки и профилактические правила

**CANDIDATE** означает полезный вывод из истории, ещё не подтверждённый полной повторяемой регрессией.

## RM-LESSON-001 — Сверять API Flet с установленной версией
- **Статус:** CANDIDATE; уверенность medium.
- **Триггер:** обновление Flet или перенос кода между версиями.
- **Наблюдение:** `PopupMenuItem.__init__() got an unexpected keyword argument 'text'`.
- **Причина:** предположительная несовместимость аргумента с API; полная сверка исходника не выполнена.
- **Профилактика:** сверять API установленной версии и делать короткую структурную проверку до Android build.
- **Источник:** сообщение пользователя с traceback около 2026-09-27; исходный файл сейчас отсутствует.

## RM-LESSON-002 — Защищать функциональную baseline при изменениях HTML/БД
- **Статус:** CANDIDATE; высокая уверенность, что регрессии сообщались; причина неизвестна.
- **Наблюдение:** пользователь сообщил, что импорт из БД не добавляет рецепт, а удаление и КБЖУ пропали.
- **Профилактика:** до патча фиксировать baseline; после патча отдельно проверять добавление из БД, удаление, kcal/100 г, БЖУ и покупки.
- **Причина:** не установлена; это пользовательские наблюдения, не независимый тестовый отчёт.

## RM-LESSON-003 — Разделять нормализацию текста и доменные правила ингредиентов
- **Статус:** CANDIDATE как архитектурный вывод; требования подтверждены пользователем.
- **Наблюдение:** описанная пользователем логика hv() была слишком близка к почти точному совпадению; проблемы включали регистр, перестановку слов и падежи.
- **Профилактика:** разнести текстовую нормализацию (регистр, пробелы, формы/порядок слов) и доменные синонимы/категории/исключения; тестировать положительные и отрицательные примеры.
- **Ограничение:** требование не доказывает реализацию.

## RM-LESSON-004 — Не считать сборку чистой после ошибки очистки
- **Статус:** CANDIDATE; событие наблюдалось, связь с белым экраном не подтверждена.
- **Наблюдение:** flet clean показал Windows WinError 32 — файл permission_handler_android внутри build был занят; последующая сборка остановилась/застряла на Android этапе.
- **Профилактика:** при WinError не объявлять clean успешным; остановить конфликтующие процессы, удалить только рабочий build, проверить отсутствие каталога и затем собирать.
- **Важно:** не доказано, что старый build вызвал белый экран.

## RM-LESSON-005 — Возврат из load_html не доказывает фактический рендер
- **Статус:** CANDIDATE; вывод ограничен доступными JSON diagnostics.
- **Подтверждено diagnostics_probe2.json:** permission вернулся `PermissionStatus.GRANTED`; WebView создан; page.update завершён; задача загрузки стартовала; зарегистрировано `SCANNER_WEBVIEW_RENDER_PROBE` с base_url `https://unpkg.com/`; URL events включили `https://unpkg.com/` и `about:blank`.
- **Подтверждено diagnostics_probe3.json:** аналогичная цепочка есть; ожидаемые `SCANNER_HOST_MARKER_START/ADDED/UPDATED` отсутствуют.
- **Гипотеза о зависшем permission request:** не согласуется с событием RETURNED и статусом GRANTED.
- **Не доказано:** HTML отображён; причина белого экрана; причина отсутствия маркеров; APK собран из ожидаемого main.py.
- **Профилактика:** логировать границы цепочки; если маркеров нет, сначала подтверждать идентичность исходника, build и APK.
