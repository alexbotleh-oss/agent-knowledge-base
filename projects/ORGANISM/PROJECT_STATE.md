# PROJECT_STATE — ORGANISM

- **Проект:** ORGANISM — самостоятельное приложение непрерывного агента и внешней памяти, а не только мост к ChatGPT.
- **Исходный репозиторий приложения:** `alexbotleh-oss/organism`. Этот репозиторий не является `agent-knowledge-base`.
- **Первая платформа:** Android-телефон; взаимодействие с ИИ — через встроенный WebView-интерфейс; требование пользователя — максимальная автономность в заданных ограничениях.
- **Статус памяти:** PARTIAL — доступные чаты/сводки покрывают ключевые решения и несколько Android-инцидентов, но полного экспорта переписки и всех артефактов здесь нет.
- **Архитектурное направление:** собственная БД памяти; RAW-источники и provenance; импорт ChatGPT ZIP/TXT/MD/PDF/URL; проекты, задачи, события, действия, результаты, проверки, знания и опыт; устойчивые ID и связи; версии, неопределённость, конфликты, rejected paths, loss/coverage, change log, FTS5 и Context Engine.
- **Обязательный pipeline:** запрос → Context Engine → память/опыт/источники/проекты/решения → GPT → проверка → фиксация нового опыта и связей.
- **Подтверждённый масштаб импорта:** в одной из итераций импортированы 74 беседы / 10 034 сообщения; при этом просмотр, архивирование и поиск импортированных бесед оставались недоступными, то есть данные присутствовали в памяти, но не были интегрированы в пользовательский контур чатов.
- **Известные Android-проблемы:** ChatGPT downloads из WebView возвращали `application/octet-stream`, `bytes=0` и `content.bin`; для `chatgpt.com` подготовлен маршрут во внешний браузер. После входа/OAuth сообщался белый экран с `net::ERR_NAME_NOT_RESOLVED`.
- **Статус сборок:** в сводках отмечены успешные GitHub Actions сборки отдельных commits; это не равно подтверждённому runtime на телефоне. Исправление скачивания требовало проверки на устройстве; OAuth/WebView остаётся unresolved.
- **Ключевые ограничения:** не сводить ORGANISM к ChatGPT bridge; RAW-данные не перезаписывать структурированной интерпретацией; импорт должен создавать реально доступный архив/поиск; не объявлять Android-функции работающими по CI/build одному.
- **Следующий шаг:** восстановить live state исходного репозитория и PR/веток; устранить несвязность imported archive с UI, затем диагностировать WebView OAuth отдельно от download/attachment flows.

## Дополнительное архитектурное требование: защита целостности памяти
- По доступной сводке от 2026-10-07 пользователь установил, что память и связи критичны для целостности агента. При дефиците места нельзя автоматически удалять потенциально значимые данные.
- Требуемый порядок: безопасная очистка → обратимый карантин → проверка связности/ссылок → проверяемое восстановление; необратимое удаление должно быть защищено.
- Это требование перенесено в DEC-ORGANISM-006 и L-ORGANISM-005; реализация не подтверждена.
