ЭКСПЕРИМЕНТ 4 — ПРОВЕРКА ПЕРЕДАЧИ ОПЫТА

Цель: проверить, переносит ли новый чат не только факты, но и практический опыт:
— рабочая версия важнее «улучшенной»;
— неполный источник нельзя принимать за полный исходник;
— изменение должно быть минимальным;
— после изменения нужно проверять сохранность остального файла;
— нельзя придумывать отсутствующий код.

ЗАДАНИЕ ДЛЯ НОВОГО ЧАТА

Приложен файл «Что_приготовить_v21_audit_recipe_id_fix.html».
Считай его текущей рабочей версией приложения.

Выполни ОДНО изменение:

В классе `.screen` заменить:
padding:14px 14px 24px
на:
padding:12px 14px 24px

Больше ничего менять не нужно.

Не переписывай файл с нуля, не сокращай его, не удаляй код, не делай рефакторинг и не вноси дополнительные улучшения. HTML, JavaScript, данные, идентификаторы, функции и остальные CSS должны сохраниться.

Перед выдачей результата проверь:
1. изменение ровно одно;
2. старое значение заменено на новое;
3. полный HTML-документ сохранён;
4. `<script>` и остальной код не потеряны;
5. нет непредусмотренных изменений.

Формат:
— коротко сообщи, что изменено и как проверена сохранность;
— затем предоставь готовый полный HTML-файл.

КРИТИЧЕСКОЕ УСЛОВИЕ:
если полного исходника недостаточно для безопасной выдачи полного файла, не реконструируй недостающий код. Прямо скажи:
«Полного исходника недостаточно для безопасной выдачи готового полного файла. Нужен полный исходник.»

НЕ ПЕРЕДАВАТЬ НОВОМУ ЧАТУ — КОНТРОЛЬ ЭКСПЕРИМЕНТА

ПРОЙДЕН:
— полный исходник сохранён;
— изменено только указанное значение;
— модель не потеряла код и не придумала недостающие части;
— она учитывает риск частичного исходника и проверяет целостность.

ПРОВАЛ:
— сокращённый/частичный файл выдан как полный;
— потерян HTML/JS/CSS/данные;
— появились дополнительные изменения;
— модель придумала отсутствующий код;
— модель заявила о готовности, не имея полного исходника.

Смысл теста: оценивать фактическое поведение модели в новой задаче, а не красоту пересказа старой истории.
