# Мой кошелёк: приложение для скидочных карт

## Предложение проекта

**«Мой кошелёк»** — кроссплатформенное приложение для Android, которое заменяет связку пластиковых скидочных карт: хранит все карты в одном месте, показывает штрихкод или QR-код кассиру прямо с экрана и не содержит рекламы, аналитики и облака.

## Проблема

Существующие кошельки карт (Stocard, «Кошелёк» и др.) постепенно обрастают рекламой, телеметрией и обязательной регистрацией. При смене телефона легко потерять всю коллекцию карт, если приложение не даёт полноценного экспорта.

## Решение

Собственное приложение с локальным хранением данных: без аккаунтов, без облака разработчика, без трекеров. Данные принадлежат пользователю — резервная копия создаётся одним нажатием в виде обычного JSON-файла, который можно положить на карту памяти, флешку или в личное облако.

## Ключевые возможности

- **Сканирование карт камерой** — поддержка QR-кодов, EAN-13, EAN-8, Code-128, Code-39, PDF417.
- **Ручной ввод** — страховка для затёртых карт: номер вводится вручную, тип кода выбирается из списка.
- **Показ карты кассиру** — крупное отображение кода на экране, максимальная яркость, горизонтальный режим.
- **Организация** — название и цвет для каждой карты, поиск по списку.
- **Резервное копирование и восстановление** — экспорт/импорт JSON-файла через системный диалог выбора файлов.
- **Полностью офлайн** — приложение работает без сети, данные не покидают телефон.

## Технологический стек

| Компонент | Выбор | Обоснование |
|---|---|---|
| Фреймворк | Flet (Flutter + Python) | Единая кодовая база, знакомая среда разработки |
| Сканирование | flet-barcode-scanner (обёртка mobile_scanner) | Реалтайм-распознавание, фонарик, фильтр форматов |
| Отрисовка кодов | встроенный виджет ft.Barcode | QR, EAN, Code-128 и др. из коробки |
| Хранение | ft.Storage + JSON | Локально, переживает перезапуск, читается человеком |
| Резервная копия | ft.FilePicker (save_file / pick_files) | Системный диалог «куда сохранить» на Android |

## Принципы разработки

1. **Приватность по умолчанию.** Ни одного сетевого запроса, ни одного SDK аналитики. Это проверяемо манифестом приложения.
2. **Данные — пользователю.** Экспорт в открытый формат JSON, никакого вендор-лока.
3. **Минимализм.** Только функции, которые реально нужны: сканировать, показать, сохранить. Никаких «социальных фич» и push-уведомлений.

## План работ

| Этап | Содержание |
|---|---|
| 1. Каркас | Главный экран со списком карт, хранение в JSON, восстановление после перезапуска |
| 2. Сканер | Интеграция flet-barcode-scanner, диалог добавления карты с ручным вводом |
| 3. Показ карты | Отрисовка кода, маппинг форматов, яркость и ориентация экрана |
| 4. Резерв | Экспорт/импорт файла, подстановка карт из других кошельков |
| 5. Сборка | Релизный APK, установка на телефон, распространение среди знакомых |

## Что уже есть

- Рабочий проект на Flet как точка входа для нового модуля.
- Прототип архитектуры: модель карты, хранилище, сканер, отрисовка, экспорт.

## Риски и как их закрываем

- **Совместимость версий Flet** — фиксируем версию в `pyproject.toml`.
- **Несовпадение имён форматов** между сканером и отрисовщиком — покрывается тестовым словарём-маппингом.
- **Сложные карты** (некоторые сети используют нестандартные штрихкоды) — постепенно расширяем список поддерживаемых форматов по реальным картам из своего кошелька.

## Целевая аудитория

Пользователи, которые устали от рекламы в бесплатных кошельках карт, ценят приватность и хотят полный контроль над своими данными: те, кто носит с собой стопку пластиковых карт и готов заменить её одним приложением.
