# 2. INCIDENT-CARD-002 — регресс Web/PWA 06.10.2026

## Наблюдение

После изменения положения названия карты в режиме **«По центру»** с `50%` на `48%` карты снова исчезли на ПК.

## Корень проблемы

При подготовке изменения `c91fc8370f73aa7840e084ab5edd3f8fac9a8732` файл `index.html` был сформирован из неполного содержимого и записан как полный файл.

В результате в рабочую ветку попал неполный `index.html`, из-за чего была нарушена рабочая JavaScript-часть приложения.

## Последовательность

1. Рабочее состояние: `1c693a71c3f82e80740bd928b5b88f3562d58b3d`.
2. Требовалось только поднять центральное название с `50%` до `48%`.
3. При записи был использован неполный файл.
4. Пользователь обнаружил регрессию: карты исчезли на ПК.
5. Было установлено, что причина не в localStorage, картах пользователя, GitHub Pages или Service Worker.
6. `index.html` восстановлен из рабочего состояния.
7. В восстановленный файл сохранено только требуемое изменение `50% → 48%`.
8. Восстановленный файл содержит **909 строк**.

## Восстановительный коммит

`f6d82dd45b9137cad7b316ce7f16837a0a367dd2`

Статус: **восстановление выполнено; пользовательская E3-проверка ещё требуется.**

# 4. Нарушенный контроль

При сегодняшнем изменении не был выполнен полный контроль:

- SHA-VERIFY;
- получение полного исходного файла перед полной записью;
- проверка целостности после записи;
- reverse-diff;
- обязательный regression-контур до выдачи результата.

Причина регрессии — нарушение процедуры безопасного изменения файла.

---

# 5. Обязательный контроль после INCIDENT-CARD-002

## Перед изменением

1. Определить последнее рабочее состояние.
2. Зафиксировать SHA.
3. Сделать PRE-CHANGE SNAPSHOT.
4. Получить полный файл, если файл будет полностью перезаписываться.

## Во время изменения

5. Вносить только один заявленный change.
6. Не переносить в рабочий файл неполные диапазоны как будто это полный файл.

## После изменения

7. Повторно прочитать именно записанный файл.
8. Проверить его полноту.
9. Проверить наличие критических JS-блоков.
10. Выполнить reverse-diff относительно предыдущего рабочего состояния.
11. Проверить, что изменён только заявленный слой.
12. Выполнить regression.
13. Только после этого переходить к следующему изменению.

# 6. Запрет на частичный файл

Для CARD111 действует обязательное правило:

> **Частично прочитанный `index.html` никогда не использовать как источник для полного `update_file`.**

Если нужен небольшой участок для анализа — можно читать участок.

Если файл нужно записать целиком — сначала необходимо получить полный файл.

# 15. Правило дальнейшей разработки

Рабочий цикл CARD111:

**Рабочий SHA → Snapshot → Один change → Проверка файла → Reverse-diff → Regression → E3 → следующий change.**

Нельзя переходить к следующему изменению только потому, что конкретная строка визуально исправилась.

# 16. Текущая контрольная точка

Последнее состояние:

`f6d82dd45b9137cad7b316ce7f16837a0a367dd2`

Это **восстановительный коммит**, а не новый утверждённый WP.

До пользовательской проверки нельзя считать его окончательно рабочим состоянием.

Следующая проверка должна начинаться с:

1. отображения карт на ПК;
2. открытия существующей карты;
3. проверки редактора;
4. проверки положения названия;
5. проверки сохранения.

Только после этого разрешается следующий UI change.
