# Протокол контроля и проверки каждого шага

## Обязательное правило
Каждое значимое изменение проходит цикл Baseline → Hypothesis → Change → Verification → Record. Чем выше риск, тем строже и независимее проверка. Нельзя откладывать все проверки до конца задачи.

## Перед изменением
- Сформулировать требование и наблюдаемое ожидаемое поведение.
- Определить затронутые компоненты, зависимости и возможные регрессии.
- Зафиксировать ветку, commit, состояние дерева и baseline тестов, если доступны.
- Выбрать проверку заранее.
- Отделить факт от гипотезы о причине.
- Для необратимого действия проверить разрешение и предусмотреть восстановление.

## После каждого логического шага
- Проверить diff/артефакт и синтаксис/структуру.
- Запустить наиболее узкий релевантный тест.
- Проверить соседние функции при риске регрессии.
- Для UI — повторно отрендерить и сравнить с эталоном; для сборки — проверить результат и запуск, не только команду сборки; для данных — сверить количество, ID, схему и связи.
- Записать PASS/FAIL/BLOCKED/SKIP/NOT RUN и доказательство.
- При неудаче остановить наращивание изменений, диагностировать и исправить.

## Перед итогом
- Пройти критерии приёмки по одному.
- Проверить соседние требования на регрессию.
- Сверить результат с исходной целью.
- Проверить соответствие документации и реализации.
- Оставить точный handoff и список незапущенных проверок.

## Запрещённые подмены
- Файл создан ≠ функция работает.
- Код выглядит верно ≠ тест прошёл.
- CI запущен ≠ CI прошёл.
- Нет ошибки в видимом логе ≠ ошибок нет.
- VLM согласен ≠ визуальная проверка доказана.
- Новая версия существует ≠ её надо немедленно обновить.
- Документ описывает мониторинг ≠ мониторинг работает.
